# 主动复习队列说明

## 这个功能解决什么问题

课堂笔记生成以后，如果学生只浏览一遍，过几天往往会忘记。主动复习队列把每条成功笔记里的“待复习问题”收集起来，让学生先回忆答案，再查看笔记摘要和知识点。

## 学生看到的使用流程

```text
首页点击“开始复习”
→ 系统从所有成功笔记中收集问题
→ 每次只显示一道问题
→ 学生先在心里回答
→ 点击“显示答案”
→ 查看摘要、关键知识点和教材来源
→ 选择“再看看”或“会了”
→ 完成一轮后显示统计
```

下一轮复习时，“再看看”的问题排在最前，没有复习过的问题排在中间，“会了”的问题排在最后。

## 数据怎样保存

注意笔记和笔记文件仍然是原来的 `files/notes.json`。这个功能没有改动原有笔记格式。

复习结果单独保存在：

```text
files/review_progress.txt
```

文件第一行是版本标记，后面的每一行代表一道题的结果。问题原文会先转换成十六进制文本，因此中文、空格和换行不会破坏文件结构。

## 问题编号为什么不是数组下标

一条笔记的问题可能在编辑后重新排序。如果使用“第 0 个问题、第 1 个问题”作为编号，排序变化会导致复习记录对应到错误的问题。

当前编号由两部分计算：

```text
笔记 ID + 问题原文
```

再通过 SHA-256 转成固定长度的编号。这里不需要学生理解算法，只需要记住一条规则：问题原文不变，问题编号就不变。

## 关键代码

- `ReviewQueue.build(...)`：只筛选成功笔记，去掉空问题，并按“再看看、未复习、会了”的顺序排列。
- `ReviewStore`：读取和保存复习结果。
- `ReviewActivity`：控制问题、答案、按钮和本轮完成页面的切换。
- `MainActivity`：在首页增加“开始复习”入口。

## 为什么这一版不调用 AI

课堂中已经生成过问题和知识点。复习时直接使用这些内容即可，再次调用 AI 会增加等待时间和费用。第一版先保证复习流程稳定，后续再考虑根据学生表现自动生成新问题。
