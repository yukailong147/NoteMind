# AI 接入与状态说明

本版本把“拍照后直接写入模拟内容”改成了可替换的生成流程：

```text
拍照
→ 保存原图
→ 创建待整理草稿
→ 进入详情页
→ 调用生成器
→ 整理成功或失败
→ 保存状态
```

默认没有配置 AI 接口时，应用使用模拟生成器，因此仍然可以完成全部界面和保存测试。

## 四种笔记状态

### 待整理

拍照完成，原图已经保存，但还没有整理结果。

### 整理中

应用已经调用生成器。此时显示进度条，不应重复提交。

### 整理完成

生成器返回标题、摘要、知识点、问题、关键词和不确定内容，并保存到 `notes.json`。

### 整理失败

原图和草稿不会被删除。详情页显示错误原因，并提供“重新整理”按钮。

## 测试失败与重试

当前默认使用模拟生成器。把首页课程名称改成：

```text
模拟失败
```

然后拍摄或生成示例板书。模拟生成器会故意返回网络错误，用于验证：

- 失败状态能否保存。
- 原图是否仍然保留。
- 错误信息是否显示。
- “重新整理”按钮是否出现。

第一次进入详情页后会自动失败。保持当前页面并点击“重新整理”，模拟服务第二次会返回成功，用于验证重试流程。

## 接入真实 AI

当前网络实现采用常见的 OpenAI 兼容聊天接口，并要求服务能够读取 `image_url` 形式的数据 URL。已经确认 `deepseek-flash` 支持这种方式，专用步骤见 `DeepSeek接入说明.md`。

在项目根目录的 `local.properties` 中加入：

```properties
AI_ENDPOINT=https://你的服务地址/v1/chat/completions
AI_IMAGE_MODEL=支持图片输入的模型名称
AI_API_KEY=你的开发密钥
```

不要修改字段名。接口地址应当填写完整的请求地址，而不是只有域名。

配置后重新构建应用，生成器会自动从模拟实现切换到真实实现，不需要修改页面代码。

## 请求格式

应用会发送：

```text
system 消息：
要求模型只返回固定 JSON 字段，并禁止补写图片中不存在的内容。

user 消息：
1. 文本：课程名称和整理要求。
2. 图片：压缩后的 JPEG 数据 URL。
```

期望模型返回：

```json
{
  "title": "二叉树的中序遍历",
  "summary": "80 至 180 字的整理摘要",
  "key_points": ["知识点一", "知识点二"],
  "questions": ["待复习问题一"],
  "keywords": ["检索关键词一", "检索关键词二"],
  "uncertain": ["无法确认的文字或公式"]
}
```

模型偶尔用 Markdown 代码块包住 JSON 时，应用会截取第一个 `{` 到最后一个 `}` 并解析。字段缺失、标题为空、摘要为空或接口返回非 2xx 状态时，会进入失败状态。

## 图片处理

发送前会将图片长边缩放到不超过 1600 像素，再以 JPEG 质量 82 压缩。这样可以减少上传体积，同时保留板书文字的可读性。

## 代码模块

| 文件 | 职责 |
|---|---|
| `AiNoteGenerator.kt` | 统一的笔记生成接口 |
| `MockAiNoteGenerator.kt` | 无网络模拟实现 |
| `RemoteAiNoteGenerator.kt` | 真实 HTTP 请求、图片压缩和 JSON 校验 |
| `AiNoteGeneratorFactory.kt` | 根据配置选择模拟或真实实现 |
| `NoteStatusUi.kt` | 四种状态的文字和颜色 |
| `NoteDetailActivity.kt` | 状态切换、生成和重试 |

## 密钥限制

把 Key 写入 `local.properties` 不会进入 Git，但构建后仍可能从 APK 中提取。因此这种方式只适合本地开发和比赛演示准备。

正式公开版本不能直接携带服务密钥。届时需要一个很小的中转服务，由中转服务保存 Key，手机只调用中转服务。
