# 第一条功能链说明

> 版本说明：本文记录 v0.1 的拍照和本地保存链路。v0.2 已将生成部分改造成“草稿、整理中、成功、失败”四状态，并加入可配置真实 AI。当前版本的接口配置和测试方法见 `AI接入与状态说明.md`。

这条功能链已经完成并在 Android 模拟器中运行：

```text
首页输入课程
→ 调用系统相机或生成测试板书
→ 创建一条使用固定模拟数据的笔记
→ 把照片保存到手机
→ 把笔记信息写入 notes.json
→ 首页重新读取并显示笔记
→ 点击笔记进入详情页
→ 强制关闭应用后重新打开，笔记仍然存在
```

当前没有调用真实 AI。“模拟整理结果”是刻意保留的测试边界，用来先验证拍照、数据保存、页面跳转和重新读取。

## 页面如何工作

### 首页

文件：

```text
app/src/main/java/com/team/classroomnotes/MainActivity.kt
app/src/main/res/layout/activity_main.xml
```

`activity_main.xml` 只描述屏幕长什么样：

- 课程输入框
- 拍摄按钮
- 测试按钮
- 状态文字
- 笔记数量
- 可滚动的笔记区域

`MainActivity.kt` 负责行为：

- 程序启动时加载笔记。
- 点击拍照时打开系统相机。
- 拍照返回后复制照片。
- 创建模拟笔记。
- 把笔记卡片填进首页。

### 详情页

文件：

```text
app/src/main/java/com/team/classroomnotes/NoteDetailActivity.kt
app/src/main/res/layout/activity_note_detail.xml
```

首页只把笔记编号传给详情页。详情页再根据编号从本地存储中找到完整笔记。这样列表页不需要携带整条笔记，数据只有一个来源。

## 最重要的一次点击发生了什么

点击“拍摄板书”后，程序依次执行：

```text
读取课程名称
→ 在 cache/camera 创建临时照片文件
→ 通过 FileProvider 生成安全的 content:// 地址
→ 请求系统相机拍照并写入这个地址
→ 相机返回是否成功
→ 把临时照片复制到 files/photos
→ 生成 NoteItem
→ NoteStore 写入 files/notes.json
→ 首页重新渲染笔记卡片
```

临时照片放在缓存目录，是因为它只用于相机写入。拍照成功后，应用会把照片复制到自己的长期私有目录；拍照取消时，临时文件会被删除。

FileProvider 是 Android 的安全文件接口。相机属于另一个应用，不能直接写我们应用里的普通文件路径，所以需要通过一个临时授权地址来交换图片。

## 一条笔记的数据结构

文件：

```text
app/src/main/java/com/team/classroomnotes/data/NoteItem.kt
```

```kotlin
data class NoteItem(
    val id: String,
    val courseName: String,
    val title: String,
    val summary: String,
    val keyPoints: List<String>,
    val questions: List<String>,
    val imagePath: String,
    val createdAt: Long,
    val isMock: Boolean
)
```

字段含义：

- `id`：每条笔记的唯一编号。
- `courseName`：所属课程。
- `title`：笔记标题。
- `summary`：模拟整理摘要。
- `keyPoints`：知识点列表。
- `questions`：待复习问题列表。
- `imagePath`：原图保存位置。
- `createdAt`：创建时间。
- `isMock`：是否来自模拟数据。

`data class` 是 Kotlin 中专门保存数据的类。编译器会自动提供比较、复制和打印等基础能力。

## JSON 如何保存

文件：

```text
app/src/main/java/com/team/classroomnotes/data/NoteStore.kt
```

`NoteStore` 做三件事：

1. `loadAll()`：读取 `notes.json` 并转换为 `List<NoteItem>`。
2. `add()`：增加一条笔记并重新写回文件。
3. `findById()`：按编号找到详情页需要的笔记。

JSON 是带字段名的文本数据。它便于当前阶段检查和排错，例如可以直接运行：

```powershell
adb shell run-as com.team.classroomnotes cat files/notes.json
```

现在不引入数据库，因为第一版数据量小，JSON 足以完成任务。以后笔记数量增加，再评估本地数据库。

## Kotlin 概念对应

### `val` 和 `var`

- `val`：只能赋值一次，适合笔记 ID、标题和文件路径。
- `var`：可以再次赋值，例如当前等待处理的照片文件。

### 空值

`String?` 表示这个值可能是空。例如：

```kotlin
private var pendingPhotoFile: File? = null
```

表示当前可能没有正在等待相机返回的文件。使用它之前必须检查是否为空。

### Lambda

```kotlin
captureButton.setOnClickListener { openSystemCamera() }
```

大括号中的内容是一个函数，用户点击按钮时执行。它等价于“以后被点击时，请运行 `openSystemCamera()`”。

### `when`

当前程序暂时使用简单的 `if`。以后处理“处理中、成功、失败、字段不完整”等状态时，会使用 `when`，它类似 C++ 的 `switch`。
